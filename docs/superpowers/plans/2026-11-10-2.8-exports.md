# Profile Schema 2.8 — Exports — Implementation Plan

**Spec:** `docs/superpowers/specs/2026-11-09-profile-schema-2.6-2.8-design.md` §6. **Tracking:** #27. One PR per issue.

**Goal:** the profile leaves in the formats other systems read: GEDCOM 7.0 and 5.5.1, Open Badges 3.0 / CLR 2.0, Europass, HR Open, and a plain-text ATS résumé.

**Rule for every export:** a mapping (or a mapping plus a small writer) so the same filter, content rules and helpers apply; golden files in `examples/out/` regenerated and diffed in CI; and, where the standard publishes something machine-readable, the tests check against it offline.

## Task 1: GEDCOM 7.0 and GEDZip (#21)

- [x] First step: read the standard, not memory. FamilySearch publishes its structure rules as tables (`substructures.tsv`, `cardinalities.tsv`, `payloads.tsv`, `enumerationsets.tsv`) and test files; both are vendored in `upstream/gedcom7/` (Apache 2.0).
- [x] `test/gedcom-check.mjs`: a checker driven by those tables (tag placement, cardinality, date grammar, enumerations, pointers, declared extensions). It must accept `maximal70.ged`, `minimal70.ged` and `escapes.ged` before it is used on our output.
- [x] `mappings/gedcom7.json` builds a view (names, facts, media, sources); `"format": "gedcom7"` hands it to `renderGedcom7` in `lib/gedcom.mjs`.
- [x] Facts: `OCCU` per position (employer at the time as `AGNC`), `EDUC`, `RESI`, `EVEN` with `TYPE` for timeline events and service.
- [x] Dates: `gedcomDateValue` (ABT, EST, CAL, BEF, AFT, BET…AND) and `gedcomPeriod` (FROM…TO; a lone date is a moment; an uncertain end adds a `PHRASE`).
- [x] Citations: `SOUR` pointer, `PAGE`, `DATA`/`TEXT` for a quote, `QUAY` (primary 3, secondary and published 2, selfReported 1, hearsay 0). Only cited sources are written.
- [x] `OBJE` records for approved public media; `_CONF` extension declared in `HEAD.SCHMA`.
- [x] GEDZip: `storeZip` (store-only, deterministic, no dependency), `--gedzip` on `convert`, media read only from inside the bundle. The tests' zip reader is first proved on `maximal70.gdz`.
- [x] `examples/out/*.ged` regenerated and diffed in CI.

**Not done:** no GEDCOM program has imported the files. Credentials, awards, projects, publications, skills and languages are not exported.

## Task 2: GEDCOM 5.5.1 (#22)

- [x] First step: the specification, not memory. 5.5.1 has no tables, so its structure definitions and size limits were extracted from the PDF's text into `upstream/gedcom551/grammar.txt` (the specification permits copying for programming genealogical software, with its notice). No official 5.5.1 test files were found.
- [x] `test/gedcom551-check.mjs` parses that grammar (references, alternatives, cardinalities, sizes) and adds the prose-only rules by hand: dates, doubled at-signs, the 255 line limit, three enumerations.
- [x] `mappings/gedcom551.json` is `"extends": "gedcom7"` with `"format": "gedcom551"`: the same view, another writer (`renderGedcom551`). `resolveMapping` does the merge.
- [x] `GEDC VERS 5.5.1`, `FORM LINEAGE-LINKED`, `CHAR UTF-8`, `SUBM`, languages by name, `OBJE` with `FILE`/`FORM`/`TYPE`, every `@` doubled.
- [x] `CONC`/`CONT` within 255 bytes per line, never breaking beside a space, inside `@@` or before a combining mark.
- [x] 7.0-only structures become `NOTE`s (date phrase, `_CONF`, the value of `RESI` and `EVEN`); over-long values are cut at their limit and kept whole in a note. A test checks every piece of 7.0 text is present in the 5.5.1 file.
- [x] Two deliberate deviations, documented and tested: file references over 30 characters; formats outside the 5.5.1 list.

## Task 5: HR Open Standards (#25)

## Task 6: Plain-text ATS résumé (#26)

- [x] `mappings/ats.json` extends `resume` (`"format": "ats"`, `"followsTargets": ["resume"]`); `lib/ats.mjs` writes one column of text: capital headings, `datesNumeric` with a plain hyphen, links in full, `- ` bullets.
- [x] A test requires every string of the résumé view to be in the text, for all five examples, so it says what the PDF says.
- [x] `examples/out/*.ats.txt` regenerated and diffed in CI. Not done: no ATS parser has been run on the output.
