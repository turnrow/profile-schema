# Profile Schema 2.7 — Review file and accessible PDF — Implementation Plan

**Spec:** `docs/superpowers/specs/2026-11-09-profile-schema-2.6-2.8-design.md` §5. **Tracking:** #27. One PR per issue, in this order.

**Goal:** A reviewer can read the whole profile in one accessible file and see where every entry will appear; a résumé PDF that passes PDF/UA-1 is rendered from a shared view model.

**Tech stack:** Node ≥ 20, ESM, `node:test`. No new runtime dependencies for Task 1 and Task 2. Typst and veraPDF are pinned build tools for Tasks 3 and 4, not npm dependencies.

## Task 1: `review` (#16)

- [x] `inclusion(entry, include, target)` in `lib/convert.mjs` returns `{ shown, reason }`; `convert`'s own filter calls it, so the review file and the outputs can't disagree.
- [x] `sectionsRead(mapping)` lists the top-level lists a mapping's template reads.
- [x] `lib/review.mjs`: `reviewMarkdown(profile, { on, locale, bundleDir, mappings, source })`.
  - Summary: consent, validation, counts by status, confidence and visibility, open items (disputed, pending, question), rule hits per output.
  - The person: fields and names with visibility.
  - Entries by section: id, what it says, status, confidence, visibility, sources (quality), codes, notes, outputs. Positions, responsibilities and figures get their own rows and inherit from their entry.
  - Claims and disputes: one row per claim beside the profile's value.
  - Other people's data: people, words written by others with consent and scope, references. Contact values are not printed.
  - Audiences and releases.
- [x] Profile text is escaped so it can't start Markdown or break a table.
- [x] An invalid profile still gets a file, headed by its errors.
- [x] CLI `review`; `.gitignore` for review files; `examples/out/sample.review.md` regenerated and diffed in CI.
- [x] Tests in `test/review.test.mjs`, including the accessibility rules (one H1, no skipped levels, header rows, no symbols for status).

**Known limits, stated in the file:** a mapping's `$where` and `$limit` are not applied, and an entry reached only through `lookup` (not a `$$.section` list) reads as "not used".

## Task 2: résumé view model (#17)

- [x] `mappings/resume.json` emits neutral JSON: `title`, `locale`, `direction`, `person` (with the photo in force, square rendition, alt text), `summary`, and ordered `sections[]` of `{ id, heading, entries }`.
- [x] Every entry has one shape (`id`, `priority`, `title`, `organization`, `location`, `detail`, `dates`, `datesNumeric`, `summary`, `bullets`, `keywords`, `url`); a job adds `positions`, newest first.
- [x] Helpers `label`, `labelFor`, `section`, `count`, `direction`, `onDate`; the `numeric` date format (MM/YYYY) for the ATS text.
- [x] Headings and levels in en, es, fr, de, pt; a test requires every language to translate every phrase.
- [x] `examples/out/*.resume.json` regenerated and diffed in CI; tests in `test/resume.test.mjs`.
- [ ] Shared by the PDF (Task 3) and the plain-text ATS résumé (#26, in 2.8). For the PDF, pass the bundle folder as `mediaBaseUrl` so `bundle:` photos resolve to local files.

**Left to the consumer:** the order in which to drop entries when a page overflows is not precomputed; each entry carries `priority`, and the `pdf` command (Task 3) ranks them.

## Task 3: accessible PDF with Typst (#18)

- [ ] `templates/resume/classic.typ`, rendered with `--pdf-standard ua-1`.
- [ ] `turnrow-profile pdf <profile> [--pages 1|auto] [--photo|--no-photo] [--locale] [--on]`.
- [ ] One-page mode fails and names what to drop when the content overflows.
- [ ] The first step confirms the current Typst version's PDF/UA support and flags from its documentation.

## Task 4: veraPDF in CI and the manual AAA checklist (#19)

- [ ] CI pins Typst and veraPDF, renders every example PDF and fails on any PDF/UA-1 violation.
- [ ] A pull request template with the checks automation can't make: screen reader, reading order, plain language.
