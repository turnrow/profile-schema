# Profile Schema 2.6 — Model: photos, people, recommendations, endorsements, badges — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Schema 2.6.0 holds versioned photos tied to dates and positions, a registry of other people with dated names, roles and contacts, recommendations with verbatim highlights and consent, skill endorsements, and badges in Open Badges 3.0 terms. The existing outputs and releases carry all of it safely.

**Architecture:**
- **Schema:** new `$defs` (`mediaAsset` fields, `personRef`, `person`, `recommendation`, `endorsement`, `badge`) added to `schema/profile.schema.json` by small, reviewed edits, as in 2.5.
- **Logic:** cross-reference and consent checks in `lib/validate.mjs`; the new logic goes in focused modules (`lib/media.mjs`, `lib/people.mjs`, `lib/badges.mjs`) so `validate.mjs` and `convert.mjs` only call them.
- **Outputs:** helpers in `convert.mjs`; mapping changes are JSON edits.

**Tech Stack:** Node ≥ 20, ESM, `node:test`, ajv 2020 (no new runtime dependencies; PNG/JPEG/SVG parsing is a few hundred lines in `lib/media.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-09-profile-schema-2.6-2.8-design.md` (§4, §7).

## Global Constraints

- **Version.** `schemaVersion` enum gains `"2.5.0"` → adds `"2.6.0"`. Files declaring 2.5.0 or earlier stay valid. New errors that would break older files apply only when `versionAtLeast(schemaVersion, "2.6.0")`.
- **Dependencies.** No new runtime dependencies (`ajv`, `ajv-formats` only).
- **Third-party data is private by default.** People's `contacts[].visibility` defaults to `"private"`. A public or network recommendation or endorsement needs `consent.given: true`.
- **Notes never render.** `note` and `rationale` are stripped by `withoutNotes` before any mapping runs; new sections inherit this.
- **Location metadata is never stored.** A bundle JPEG/PNG with GPS tags is a validation error from 2.6.0.
- **Originals are never altered.** A badge's `credential.file` is kept byte for byte; its `sha256` must match.
- **US English** in all prose, docs and outputs (license, color, localization). Identifiers that already exist keep their spelling.
- **Commits** carry this session's trailers. **One PR per task-issue**, stacked on the previous one: Task 1 on `codes-2.5`, each next task on the previous branch.
- **CI** regenerates `examples/out/*` and diffs. Every task that changes an output regenerates them in the same commit.

## Review Focus

1. **A recommendation with smart quotes or different whitespace than its highlight.** "Verbatim" compares after Unicode NFC and collapsing runs of whitespace, but not quote style. A highlight with straight quotes against a body with curly quotes fails, with a message showing the first differing character. Task 4 tests this.
2. **An author whose consent scope is `highlights`.** The full text must not appear in any output, including the LinkedIn sheet and JSON Resume `references`. Task 8 tests every mapping for the absence of the full text.
3. **A photo whose GPS tags sit in an XMP packet rather than EXIF.** The check reads both. Task 1 tests a PNG with an `iTXt` XMP chunk containing `exif:GPSLatitude`.
4. **Two images for the same purpose with overlapping dates.** This warns, and the output picks the one with the later `from`. Task 1 tests it.
5. **A baked OB 2.0 PNG whose embedded assertion is a URL, not JSON.** Import records the URL as `credential.url` with `format: ob2-hosted` and keeps the PNG as the file. It doesn't fail or fetch. Task 7 tests it.

### Task 1: Media assets, dated person images, media on positions (issue: media)

**Files:**
- Modify: `schema/profile.schema.json` ($defs `media`, `person`, `position`, `responsibility`)
- Create: `lib/media.mjs`, `test/media.test.mjs`
- Modify: `lib/validate.mjs`, `lib/convert.mjs`, `mappings/schemaorg.json`, `mappings/brief.json`, `mappings/jsonresume.json`

**Interfaces:**
- Produces:
  - `readImageInfo(buffer: Buffer): { mediaType, width, height, gps: boolean, gpsWhere: string[] }`, where `gpsWhere` is a subset of `["exif", "xmp"]`;
  - `stripGps(buffer: Buffer, mediaType): Buffer`;
  - `imageFor(profile, ref?: {entry?, position?}, on?: string): mediaView | undefined`.
- Schema fields:
  - `media`: `uuid` (format `uuid`), `version`, `supersedes` (id), `capturedOn` (fuzzyDate), `kind` (enum `headshot, portrait, banner, logo, photo, document, video, audio`), `width`, `height`, `byteSize`, `focalPoint {x, y}` (0–1), `renditions[] {url, width, height, sha256, purpose (square | banner | print | thumbnail)}`, `credit`, `copyrightHolder`, `license`, `consent {given, on}`, `contentCredentials {url | embedded: true}`, `metadata {dateTimeOriginal, make, model, software}`, `alt` (text), `longDescription`;
  - `person.images[] {media (id), purpose (primary | headshot | banner), from, to}`;
  - `media: [id]` on `position` and `responsibility`.

- [ ] **Step 1: Write the failing tests.** In `test/media.test.mjs`:
  - `readImageInfo reads PNG and JPEG dimensions`: 1×1 PNG → `{mediaType: "image/png", width: 1, height: 1, gps: false}`.
  - `GPS is found in EXIF and in XMP`:
    - a JPEG with an APP1 Exif GPS IFD → `gpsWhere` `["exif"]`;
    - a PNG with an `iTXt` XMP chunk containing `exif:GPSLatitude` → `["xmp"]`.
  - `stripGps removes both, keeps pixels`: after stripping, `readImageInfo(...).gps === false`, the IDAT/scan bytes are unchanged and the dimensions are equal.
  - `validate (2.6): a bundle image with GPS is an error; in 2.5 a warning`.
  - `validate: an image without alt warns`.
  - `validate: unknown media id on a position errors`.
  - `imageFor picks the dated image in force, the later 'from' when two overlap, and warns on the overlap`.
  - `imageFor(position) prefers the position's media, then the job's, then the person image in force at the position's start`.
  - `schema.org image uses imageFor(on) and the 'square' rendition when present`.

  Fixtures are built in the test from bytes (no binary files committed in this task).
- [ ] **Step 2: Run** `node --test test/media.test.mjs`. Expected: FAIL (module not found).
- [ ] **Step 3: Implement `lib/media.mjs`:**
  - PNG: chunk walk (`IHDR` for size, `eXIf`/`iTXt`/`tEXt` for XMP).
  - JPEG: segment walk (SOFn for size, APP1 `Exif\0\0` → TIFF IFD0 tag `0x8825` GPS pointer, APP1 XMP `http://ns.adobe.com/xap/1.0/`).
  - SVG: `width`/`height`/`viewBox` attributes; GPS is never present.
  - `stripGps`: drop the GPS IFD pointer and data from Exif. Remove `exif:GPS*` properties from XMP by regex on the packet's attributes and elements, then rewrite the length and CRC (PNG) or the segment length (JPEG).
- [ ] **Step 4: Schema and validator:**
  - add the fields;
  - in `checkBundle`, read each image file with `readImageInfo`: GPS → error (2.6) or warning;
  - `alt` missing on an image `mediaType` → warning;
  - person-image overlap → warning;
  - position and responsibility `media` ids → checked.
- [ ] **Step 5: Convert:**
  - `withPublishedMedia` also rewrites `renditions[].url`;
  - add helper `imageFor`;
  - mappings `schemaorg` (`image`), `brief` (`photo`) and `jsonresume` (`basics.image`) use `{ "$fn": "imageFor" }` with the output's `on`.
- [ ] **Step 6: Run** `npm test && npm run -s validate:examples`. Expected: all pass. Regenerate `examples/out` (no diff expected for examples without images).
- [ ] **Step 7: Commit:** "Media assets: versions, renditions, dated person images, GPS check".

### Task 7: Badge import (issue: badge import)

**Files:** Create `lib/badges.mjs`; Modify `bin/profile.mjs` (`badges import <bundle> <file|url> [--id] [--fetch]`); Test `test/badges.test.mjs`.

**Interfaces:**
- Consumes the `badges[]` shape (Task 6) and `readImageInfo` (Task 1, for baked PNG/SVG).
- Produces:
  - `parseBadge(buffer, {name?}): { entry: badge, original: Buffer, ext }`. It parses OB 2.0 Assertion JSON, OB 2.0 JWS (compact; payload decoded, not verified), baked PNG (`iTXt` keyword `openbadges`), baked SVG (`<openbadges:assertion verify="…">` or a CDATA JSON), OB 3.0 JSON-LD (`type` includes `OpenBadgeCredential` or `AchievementCredential`) and VC-JWT (payload `vc`).
  - `verifyBadge(entry, {fetch}): {status, method, checkedAt}`. In this task only `ob2-hosted` re-fetch-and-compare is implemented. Other formats return `unverified` with method `"not implemented"`, and `fetch` is injectable.

  - `a baked PNG whose iTXt holds a URL becomes ob2-hosted with the PNG as file`;
